# MASTER IMPLEMENTATION PROMPT — JANEIROTOUR.COM BLOG CONTENT PACK

Implement the seven article packages contained in this folder in the Janeiro Tour CMS. Preserve all existing site functionality and styling. Do not publish until every validation step passes.

## 1. Import and exact field mapping
For each article folder, read `seo.json` and the three Markdown files. Map fields as follows:
- `slug` → Post slug
- `category` → Category
- `author` → Author
- English title/excerpt/content → English tab
- Portuguese title/excerpt/content → Português tab
- Spanish title/excerpt/content → Español tab
- `meta_title`, `meta_description`, keywords and schema → corresponding SEO fields
- Set read time automatically from the final rendered word count
- Keep imported posts as drafts until preview approval

## 2. Content storage and rendering
Use one canonical content format. Preferred approach: sanitized HTML generated by the visual editor. If the CMS stores Markdown, convert Markdown to HTML exactly once during rendering. Never escape sanitized article HTML into visible text. Visitors must never see literal tags such as `<p>`, `<strong>`, `<ul>`, `<li>`, or `<br>`.

Prevent double conversion:
- Do not convert HTML into Markdown and back on every save.
- Detect legacy Markdown before conversion.
- Do not wrap existing paragraph tags inside new paragraph tags.
- Remove duplicated `<br>` tags and invalid nested blocks.
- Sanitize with a trusted allowlist before storage or rendering.

## 3. Visual editor
Use a complete WYSIWYG editor such as TipTap, CKEditor 5, or TinyMCE. Required controls: headings H2–H4, paragraph, bold, italic, underline, lists, links, quotes, tables, image insertion, ALT text, undo/redo, and clear formatting. The toolbar must remain sticky while the article body scrolls. Applying formatting must not lose text selection, cursor position, language tab, or scroll position.

## 4. Modal behavior
The editor modal must have:
- Fixed header
- One central scroll container
- Sticky editor toolbar
- Fixed footer with Cancel, Preview, Save Draft, and Publish
Avoid nested scrollbars. Preserve unsaved edits when switching English, Português, and Español tabs.

## 5. Images
For every article, follow `images.md`:
- Upload one unique hero and at least two supporting licensed images
- Convert to WebP
- Store dimensions
- Use language-specific ALT text and captions
- Lazy-load supporting images
- Do not hotlink
- Do not reuse the same hero across posts
If suitable licensed images are unavailable, leave the post in draft and flag the missing media; do not publish with a broken or unrelated image.

## 6. SEO and structured data
- One H1 only: the post title generated by the template
- Article content begins with paragraphs/H2, not another H1
- Apply canonical URL from `seo.json`
- Add Article, BreadcrumbList, and FAQPage JSON-LD when FAQs exist
- Add Open Graph and X/Twitter metadata
- Add hreflang for EN, PT-BR, and ES versions
- Ensure every meta title and description fits the CMS limits without cutting words awkwardly
- Create internal links to relevant Janeiro Tour tours, packages, destination pages, and contact page; only use URLs that actually exist

## 7. Remove empty or broken posts safely
Identify posts that have no meaningful content in all languages. A post is considered empty only when:
- Title may exist, but body is blank, whitespace only, placeholder text, or fewer than 80 meaningful words; AND
- It has no valid bookings, inbound campaign links, or required redirects; AND
- It is not a system/template record.

Before deletion:
1. Export a backup of post IDs, slugs, titles, status, timestamps, language content, and SEO data.
2. Generate a review report grouped into `safe_to_delete`, `needs_review`, and `keep`.
3. Do not delete anything in `needs_review`.
4. For duplicate slugs or replaced pages, create a 301 redirect to the most relevant live article.
5. Use soft delete first. Permanently remove only after explicit administrator confirmation and a seven-day recovery window.

## 8. Post order
Order the admin list by `updated_at DESC`, then `created_at DESC`. After an edit or import, the most recently updated post must appear at the top before pagination is applied.

## 9. Quality assurance
Preview every language and test:
- No visible raw HTML or Markdown syntax
- Headings, bold, links, lists, images, and captions render correctly
- Mobile and desktop layouts
- No broken images or links
- Correct language switching and hreflang
- Sticky toolbar on long articles
- Saved content reopens without format changes
- Successful save moves post to the top
- Failed save keeps modal open and preserves content
- FAQ schema validates and matches visible FAQs

## 10. Fact checking
Before publishing, verify time-sensitive information—entry rules, visa requirements, attraction hours, ticket processes, border procedures, airport details, and safety notices—against current official sources. Do not invent prices, schedules, or guarantees. Add a `last_verified_at` timestamp to each post.

## 11. Completion report
Return a report containing:
- Imported post IDs and final URLs
- Publication status for each language
- Images uploaded and license/source records
- Redirects created
- Empty posts soft-deleted
- Posts requiring manual review
- SEO/schema validation results
- Any factual details that could not be verified
